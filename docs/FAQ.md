# 常见问题与排错

## 安装与启动

**启动报「读 config.yaml 失败」**

`-root` 必须指向包含 `config.yaml` 的目录。如果配置文件放别处，用 `-root` 指定它的父目录。

**启动报「加载模板失败」**

程序按相对路径读 `templates/`，工作目录必须是 `goapp/`：

```bash
cd goapp && ../knowledge-relay -root ..
```

systemd 里对应的是 `WorkingDirectory=/.../goapp`。

**能编译但运行报数据库错误**

检查 `-root` 下的 `data/` 是否存在且可写。程序会自动建目录和建表，但父目录没有写权限时会失败。

**想从旧版本升级**

直接换二进制重启即可。启动时会自动补齐新增的列，不会清空数据。升级前可以先用 `-check` 参数验证一遍：

```bash
./knowledge-relay -root /opt/knowledge-relay -check /opt/knowledge-relay/data/kb.db
```

## 分类

**文章总是进待定库**

按顺序排查：

1. `profiles/` 里是否有与 `config.yaml` 中 `name` 同名的 `.md` 档案。缺档案时该库不参与打分。
2. 档案是否写得足够具体。「定位」只有一句话、没有「边界与排除」的档案，模型很难区分相近的库。
3. `classify.threshold` 是否设得过高。默认 0.5，改成 0.6 以上会明显增加待定数量。
4. 查看详情页的「库打分」折叠面板，看最高分与次高分的差距。如果多个库分数接近，说明档案边界重叠，应该改档案而不是降阈值。

**两个库分数一样高**

系统会把并列最高一律判为待定，不随机选。这是刻意设计：与其猜错，不如让你在页面上点一下。若这种情况频繁出现，说明这两个库的档案需要写清「谁归谁」。

**改了档案但效果没变**

档案在每次分类时实时读取，不需要重启。若仍无变化，确认改的是 `profiles/` 下载入的那份文件（而不是仓库里的副本），并确认保存成功（页面会提示「档案已保存」）。

**分类很慢**

分类请求包含全部候选库档案和正文前 3000 字。库越多、档案越长，耗时越长。可以：

- 降低 `classify.body_chars`；
- 精简档案里重复的描述；
- 换更快的分类模型。

## 注释词

**候选词数量太多或太少**

调整 `limits.density`（每千字密度）或对应库的 `multiplier`。上下限由 `floor` 与 `hard_cap` 控制，默认 3 到 14。

**列表里的词点了写回却没出现**

理论上不会发生：候选词在入库前已经用与渲染器相同的逻辑验证过可注性。如果确实出现，检查该词是否只出现在标题、代码块或链接文字里——这些区域不参与标注。页面会把这类词列在「未命中」提示中。

**手动加词提示「正文中找不到该词」**

手动添加要求词能在正文的普通段落或列表里精确定位。可能的原因：词里有错别字、大小写不一致、词只出现在标题或代码块中。

**改了一个词的释义，想恢复成模型生成的**

点该词下方的「重新生成释义」，它会绕过缓存重新调用模型。

**多个库出现同一个词，释义不一样**

释义缓存按「词 + 库」隔离，这是有意的：同一个词在不同库里语境不同。写回时会按当前文章的库取对应释义。

## 写回

**提示「远端正文已被修改」**

说明你上次写回之后，在语雀网页端改过这篇文档。系统不会自动覆盖你的手改内容。

处理方式：

1. 打开语雀文档，确认手改内容是否需要保留；
2. 需要保留 → 把你改的内容同步到本地原文（目前需要重新导入或改数据库，比较麻烦），或直接放弃本地这次写回；
3. 不需要保留 → 在详情页点「强制覆盖远端」。

**提示「远端文档已转为 lake 格式」**

语雀网页端用富文本编辑器保存过，格式从 Markdown 变成了 lake。强制覆盖会把它改回 Markdown 并整篇替换。

**点了写回，页面跳走了但文章状态没变**

写回是后台队列异步执行的。点按钮只是「提交」，实际结果要稍等。可以刷新列表，或看日志：

```bash
sudo journalctl -u knowledge-relay -f | grep 写回
```

**写回一直失败**

看详情页顶部的错误文字和 `events` 表。常见原因：

- 语雀返回 429：触发限流，等一段时间再试；
- Token 权限不足：确认 Token 对该库有读写权限；
- 远端文档被删除：在语雀里删掉文档后，本地记录仍指向它，需要改分类或重新建档。

**改分类后旧文档还在**

程序会尝试删除旧库文档。如果 Token 没有删除权限，删除会失败并在页面提示，需要你手动去旧库清理。

**写回后语雀里排版乱了**

检查原文是否包含大量 HTML、表格或嵌套列表。渲染器会跳过这些区域不标注，但原文本身的结构会原样保留。如果是 HTML 导入的长段落，可以用 `-reflow-doc` 重排换行：

```bash
# 先 dry-run 看行数变化
./knowledge-relay -root /opt/knowledge-relay -reflow-doc 12
# 确认后再写入
./knowledge-relay -root /opt/knowledge-relay -reflow-doc 12 -reflow-force
```

## 导入

**简悦推送后没有反应**

1. 检查 Nginx 是否放行了 `/ingest/simpread`；
2. 检查 `X-Ingest-Key` 是否与 Nginx 配置一致；
3. 直接 curl 一次看返回：

```bash
curl -i -X POST https://relay.example.com/ingest/simpread \
  -H 'Content-Type: application/json' \
  -H 'X-Ingest-Key: 你的随机串' \
  -d '{"title":"测试","url":"https://example.com/a","content":"<p>正文</p>"}'
```

正常应返回 `{"ok":true,...}`。

**上传后提示已存在**

去重按原文链接和正文哈希判断。同一篇文章改了标题但正文没变，仍会被判为重复。

**扫描收件箱没找到文件**

只识别 `.md` / `.html` / `.htm`。文件处理成功后会被移到 `archive/`，所以第二次扫描不会重复处理。

## 数据与备份

**数据库在哪个文件**

`<root>/data/kb.db`。使用 WAL 模式，目录下还会有 `kb.db-wal` 和 `kb.db-shm`。

**怎么备份**

在线备份请用 SQLite 命令，不要直接复制正在写入的文件：

```bash
sqlite3 data/kb.db ".backup /backup/kb-$(date +%F).db"
```

另外备份 `profiles/`（分类档案）和 `.env`（密钥，单独保管）。

**永久删除会删语雀文档吗**

不会。永久删除只清理本地记录（连带词条与事件），语雀上的文档保持不动。这是刻意的设计，避免误删知识库。

**误删了还能恢复吗**

本地记录删除后无法在应用内恢复，语雀文档仍在。如果需要，重新导入原文会建一条新记录并生成新文档，旧文档需要手动处理。

## 安全

**能直接放到公网吗**

不能。服务没有登录校验，公网暴露等于公开你的语雀写入能力。必须放在带认证的反向代理后面，见 [DEPLOY.md](DEPLOY.md)。

**密钥会不会写进日志**

不会。程序不打印 Token 与模型密钥。但仍然建议把密钥放 `.env` 并设置文件权限为 600。

**可以多个人一起用吗**

v1.0 按单用户设计，没有账号体系、权限隔离和操作审计。多人使用需要自己在外层做隔离。
